## 📌 О чём этот раздел

- **Разница** между именем БД в PostgreSQL и именем ИБ в кластере 1С
- **Почему `1cv8s`**, а не `1cv8`
- Пошаговое **создание ИБ через GUI-мастер**
- **Проверка** созданной базы (что лежит в PostgreSQL)
- Типичные ошибки

**Что должно получиться:** ИБ, зарегистрированная в кластере 1С и связанная с базой PostgreSQL.

## 🎯 Ключевое различие: две «ИБ»

При создании базы в 1С участвуют **две сущности**, которые часто путают:

| Понятие | Где живёт | Пример |
|---|---|---|
| **Имя ИБ в кластере 1С** | Реестр кластера (в `1c_data` volume) | `unf_test_ib` |
| **Имя БД в PostgreSQL** | Физическая база в СУБД (в `pg_data` volume) | `unf_test2` |

**Как это работает:**
1. В кластере 1С регистрируется **информационная база** с именем `unf_test_ib`
2. Она **подключается** к базе PostgreSQL с именем `unf_test2`
3. Пользователь видит **имя в кластере** (`unf_test_ib`)
4. В PostgreSQL лежит **физическое хранилище** (`unf_test2`)

**Практический вывод:** когда подключаешься тонким клиентом — указываешь **имя в кластере** (`unf_test_ib`). Когда смотришь в DBeaver/psql — видишь **имя в PostgreSQL** (`unf_test2`).

## 🛠️ Шаг 1. Почему `1cv8s`, а не `1cv8`

В установленном дистрибутиве 1С есть **два исполняемых файла**:

| Файл | Что это | Мастер создания ИБ |
|---|---|---|
| `1cv8` | Толстый клиент (обычный пользовательский) | Идёт по «пользовательскому» пути, **без опции «Без конфигурации»** |
| **`1cv8s`** | **Серверная версия** клиента | **Полный мастер**, включая «Создать новую ИБ без конфигурации» |

**Вывод:** для создания «пустой» ИБ **обязательно** использовать `1cv8s`.

⚠️ **Тонкий клиент (`1cv8c`)** — вообще **не умеет** создавать базы. Он только **подключается** к существующим.

---

## 🛠️ Шаг 2. Не создавайте БД в PostgreSQL заранее

**Это важное правило.** Можно подумать: «раз у меня есть PostgreSQL — давай я создам базу `unf_test2` заранее, а потом подключу её к 1С». **Так делать не надо.**

**Почему:** если создать базу вручную через `psql` (или DBeaver), а потом подключиться к ней из 1С — получите ошибку. 1С требует, чтобы **она сама создала базу** и настроила её определённым образом:
- Установила расширения (`mchar`, `fasttrun`)
- Создала пользователя с нужными правами
- Инициализировала схему (сотни системных таблиц)
- Настроила локаль и кодировку по своим требованиям

**Правильный подход:** в мастере 1С **поставить галочку** «Создать базу данных в случае её отсутствия» — и 1С сделает всё сама.

⚠️ **Исключение:** если у вас **уже есть** готовая база 1С (например, бэкап боевой), её нужно **восстановить** через `pg_restore`, а потом **подключить** к новой ИБ в кластере. Но для **чистого стенда** — так не делаем.

## 🚀 Шаг 3. Запуск GUI-контейнера

См. [раздел 05](05-x11-forwarding.md) про настройку X11.

### 3.1. Убедиться, что VcXsrv запущен

Иконка VcXsrv должна быть в системном трее Windows.

### 3.2. Разрешить X-серверу подключения

На Ubuntu VM:

```bash
xhost +192.168.0.173
```

### 3.3. Запустить GUI-контейнер

```bash
cd ~/projects/1c-server
docker compose run --rm \
  -e DISPLAY=192.168.0.129:0.0 \
  -v 1c-server_1c_data:/home/usr1cv8 \
  1c-server bash
```

**Важные параметры:**
- `-e DISPLAY=192.168.0.129:0.0` — куда слать графику
- `-v 1c-server_1c_data:/home/usr1cv8` — **тот же volume**, что у основного сервера (чтобы ИБ сохранилась)

### 3.4. Проверить сеть

Внутри контейнера:

```bash
getent hosts 1c-server
getent hosts pg-1c
(echo > /dev/tcp/1c-server/1540) 2>/dev/null && echo "1c-server:1540 OPEN" || echo "CLOSED"
(echo > /dev/tcp/pg-1c/5432) 2>/dev/null && echo "pg-1c:5432 OPEN" || echo "CLOSED"
```

**Ожидаемо:** оба `OPEN`.

### 3.5. Запустить `1cv8s`

```bash
export GDK_BACKEND=x11
export LIBGL_ALWAYS_INDIRECT=1
/opt/1cv8/x86_64/8.3.26.1540/1cv8s -DisableHWA
```

**Ожидаемо:** на Windows откроется окно **«Запуск 1С:Предприятия»**.

## 🎨 Шаг 4. Мастер создания ИБ — пошагово

### 4.1. Нажать «Добавить»

В окне «Запуск 1С:Предприятия» нажмите **«Добавить»**.

### 4.2. Выбрать «Создать новую информационную базу»

На первом шаге мастера:
- ✅ **Создать новую информационную базу**
- ✅ **Без конфигурации** ← **важно!**
- Нажать **«Далее»**

### 4.3. Ввести имя ИБ

| Поле | Значение |
|---|---|
| **Имя информационной базы** | `unf_test_ib` (или любое, какое хотите) |

**Что это:** «человеческое» имя, которое будет отображаться в списке баз и при подключении.

### 4.4. Выбрать тип расположения

| Вариант | Что выбираем |
|---|---|
| **На этом компьютере** | ❌ Не подходит — база файловая, не в PostgreSQL |
| **На сервере 1С:Предприятия** | ✅ **Наш вариант** |

### 4.5. Параметры кластера

| Поле                                   | Значение                                |
| -------------------------------------- | --------------------------------------- |
| **Кластер серверов 1С:Предприятия**    | **`1c-server:1540`**                    |
| **Имя информационной базы в кластере** | `unf_test_ib` (совпадает с именем выше) |

⚠️ **Важно:** **имя контейнера `1c-server`, а не `localhost`.** Мы находимся в GUI-контейнере, но `ragent` работает в **другом контейнере** — GUI видит его по имени `1c-server` в Docker-сети.

### 4.6. Параметры СУБД

| Поле | Значение |
|---|---|
| **Тип СУБД** | **PostgreSQL** |
| **Сервер баз данных** | **`pg-1c`** |
| **Имя базы данных** | `unf_test2` (или любое другое) |
| **Пользователь базы данных** | `postgres` |
| **Пароль пользователя** | `Str0ngP@ss` |
| **Смещение дат** | `0` (по умолчанию) |
| **☑ Создать базу данных в случае её отсутствия** | ✅ **галочка включена** |
| **Язык (Страна)** | русский (Россия) |

**Почему `pg-1c`:** это **имя контейнера PostgreSQL** в Docker-сети. Он виден из GUI-контейнера по этому имени.

**Почему галочка «Создать БД»:** пусть 1С **сама** создаст базу `unf_test2` в PostgreSQL с нужными расширениями и локалью.

### 4.7. Завершение

Нажать **«Далее»** → **«Готово»**.

**Что произойдёт** (в логах PostgreSQL):
1. 1С подключится к `pg-1c:5432`
2. Создаст базу `unf_test2` с `ENCODING=UTF8`, `LC_COLLATE=ru_RU.UTF-8`
3. Установит расширения `mchar`, `fasttrun`
4. Создаст **схему 1С** — сотни таблиц (`_Reference*`, `_Document*`, `_Config` и т.д.)
5. Зарегистрирует ИБ в кластере 1С

**После завершения** база появится в списке, и можно будет подключиться к ней в режиме «Предприятие» или «Конфигуратор».

## 🔍 Шаг 5. Проверка созданной базы

### 5.1. Проверить, что БД создана в PostgreSQL

**С хоста Ubuntu:**

```bash
docker exec -it pg-1c psql -U postgres -c "\l"
```

**Ожидаемо:** в списке появится `unf_test2` (или как вы назвали).

### 5.2. Посмотреть таблицы 1С в базе

```bash
docker exec -it pg-1c psql -U postgres -d unf_test2 -c "\dt" | head -30
```

**Ожидаемо:** список таблиц с префиксами:
- `_Reference*` — справочники
- `_Document*` — документы
- `_InfoRg*` — регистры сведений
- `_AccumRg*` — регистры накопления
- `_Config` — конфигурация
- `_YearOffset` — смещение дат

### 5.3. Проверить регистрацию в кластере 1С

```bash
docker exec -it 1c-server /opt/1cv8/x86_64/8.3.26.1540/rac infobase list \
  --cluster=localhost:1540 \
  --infobase-user=admin \
  --infobase-pwd=""
```

⚠️ **Синтаксис `rac`** отличается от `rac cluster list`:
- `--cluster=` (со знаком равно)
- `--infobase-user` и `--infobase-pwd` — для ИБ
- `--admin-user` и `--admin-password` — **только** для `cluster list`

Если команда не сработает — проверьте через GUI (список баз).

### 5.4. Проверить через DBeaver (Windows)

Если у вас установлен DBeaver:
1. Подключиться к `192.168.0.173:5432`, пользователь `postgres`, пароль `Str0ngP@ss`
2. Раскрыть базу `unf_test2`
3. Раскрыть схему `public`
4. Увидите **сотни таблиц** 1С

**Это финальное доказательство**, что 1С + PostgreSQL работают вместе.

## ⚠️ Возможные ошибки

### Ошибка 1. `Сервер баз данных не обнаружен`

**Причина:** PostgreSQL не слушает на внешнем интерфейсе.

**Решение:** добавить в `docker-compose.yml`:
```yaml
command: ["postgres", "-c", "listen_addresses=*"]
```

Проверить в логах:
```bash
docker compose logs postgres | grep listening
# Ожидаемо: "0.0.0.0" и "::"
```

### Ошибка 2. `DATABASE не пригоден для использования`

**Причина:** в PostgreSQL нет расширений 1С (`mchar`, `fasttrun`).

**Решение:** использовать **1С-сборку** PostgreSQL (см. [раздел 04](04-containers.md)).

**Проверка:**
```bash
docker exec -it pg-1c psql -U postgres -c "SELECT name FROM pg_available_extensions WHERE name IN ('mchar', 'fasttrun');"
# Ожидаемо: mchar, fasttrun
```

### Ошибка 3. `Connection refused` при подключении к `pg-1c`

**Причина:** PostgreSQL не запущен, или `pg-1c` не резолвится.

**Решение:**
1. Проверить `docker compose ps` — `pg-1c` должен быть `Up (healthy)`
2. Проверить `getent hosts pg-1c` из GUI-контейнера
3. Проверить `docker compose logs postgres --tail=20`

### Ошибка 4. Ошибка лицензии при создании

**Причина:** Community-лицензия не активирована.

**Решение:** см. [раздел 07](07-license.md).

### Ошибка 5. Окно мастера не появляется

**Причина:** X11 не работает.

**Решение:** см. [раздел 05](05-x11-forwarding.md).
