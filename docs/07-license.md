## 🎯 Что такое Community-лицензия

**Community-лицензия** — это **бесплатная лицензия** 1С для **разработчиков**. Даётся через портал `developer.1c.ru`.

### Ключевые факты

| Параметр | Значение |
|---|---|
| **Кому выдаётся** | Любому, кто зарегистрирован на `developer.1c.ru` |
| **Для чего** | **Разработка и отладка**, не для реального учёта |
| **Срок** | 1 год, продлевается автоматически каждые 7 дней |
| **Слотов** | До **3-х** экземпляров на одного разработчика |
| **Привязка** | К **аппаратным параметрам компьютера** (в нашем случае — MAC контейнера) |

### Ограничения

- **Не более 3 сеансов** с прямым подключением
- **Не более 1 сеанса** через веб-сервер
- **Не более 1 сеанса** «1С:Аналитика»
- **Не более 1 сеанса** мобильного клиента
- В интерфейсе отображается **«Версия для разработчиков»**

### Требования к сети

Для активации и продления нужен **интернет**:

- Доступ к `users.v8.1c.ru`
- Доступ к `login.1c.ru`
- Валидные сертификаты `*.1c.ru`

## 📝 Шаг 1. Регистрация на developer.1c.ru

1. Откройте [https://developer.1c.ru](https://developer.1c.ru)

3. **Подтвердите номер телефона** — без этого активация не сработает
4. Запомните **логин** и **пароль** — они понадобятся при активации

⚠️ **Это отдельный портал** от `releases.1c.ru` — не путайте.

## 🛠️ Шаг 2. Подготовка: сертификаты и `/sbin/ip`

Перед активацией убедимся, что в образе `1c-server` есть всё необходимое:

### 2.1. Проверить `/sbin/ip`

```bash
docker exec -it 1c-server ls -la /sbin/ip
```

**Ожидаемо:** файл существует.

**Если нет** — добавьте `iproute2` в `Dockerfile` (см. [раздел 04](04-containers.md)).

### 2.2. Проверить сертификаты Минцифры

```bash
docker exec -it 1c-server bash -c "ls -la /usr/local/share/ca-certificates/"
docker exec -it 1c-server bash -c "grep -c 'BEGIN CERTIFICATE' /etc/ssl/certs/ca-certificates.crt"
```

**Ожидаемо:**
- В `/usr/local/share/ca-certificates/` — 2 файла: `russian_trusted_root_ca.crt` и `russian_trusted_sub_ca.crt`
- В бандле — 120+ сертификатов

**Если чего-то нет** — добавьте в `Dockerfile` (см. [раздел 04](04-containers.md)).

## 🚀 Шаг 3. Активация через GUI

### 3.1. Запустить GUI-контейнер

```bash
xhost +192.168.0.173
cd ~/projects/1c-server
docker compose run --rm \
  -e DISPLAY=192.168.0.129:0.0 \
  -v 1c-server_1c_data:/home/usr1cv8 \
  1c-server bash
```

⚠️ **`-v 1c-server_1c_data:/home/usr1cv8` обязателен!** Иначе `.lic` сохранится во временный контейнер и пропадёт.

### 3.2. Запустить `1cv8s`

```bash
export GDK_BACKEND=x11
export LIBGL_ALWAYS_INDIRECT=1
/opt/1cv8/x86_64/8.3.26.1540/1cv8s -DisableHWA
```

### 3.3. Создать пустую ИБ

Если у вас **ещё нет ИБ** (раздел 06 не пройден) — создайте пустую:
1. **Добавить** → **Создать новую ИБ** → **Без конфигурации**
2. **На сервере 1С**
3. Кластер: `1c-server:1540`
4. Имя: `license_test` (временное)
5. Тип СУБД: PostgreSQL
6. Сервер БД: `pg-1c`
7. Пользователь: `postgres`, пароль `Str0ngP@ss`
8. ☑ Создать БД

**Цель:** чтобы появился диалог **«Получение лицензии»** при попытке открыть ИБ.

### 3.4. Диалог «Получение лицензии»

При попытке открыть ИБ появится окно:

```
┌────────────────────────────────────┐
│  Получение лицензии                │
│                                    │
│  Лицензия не получена              │
│                                    │
│  Ошибка обращения к Центру         │
│  Лицензирования                    │
│                                    │
│  Показать описание ошибки          │
│                                    │
│  Хранилище сертификатов Linux      │
│  не обнаружено                     │
└────────────────────────────────────┘
```

**Что делать:**
1. Нажать **«Выбрать другой способ получения лицензии»**
2. Выбрать **«Активировать комьюнити-лицензию»**
3. Ввести **логин/пароль** от `developer.1c.ru`
4. Дождаться **«Лицензия получена»**

⚠️ **Возможные ошибки:**

| Ошибка | Причина | Решение |
|---|---|---|
| `Хранилище сертификатов Linux не обнаружено` | Нет сертификатов Минцифры | Добавить в `Dockerfile` |
| `/sbin/ip: not found` | Нет `iproute2` | Добавить в `Dockerfile` |
| `Ошибка обращения к Центру Лицензирования` | Нет интернета из контейнера | Проверить `curl https://users.v8.1c.ru` |
| `Неверный логин или пароль` | Опечатка или учётка не подтверждена | Проверить на портале |

## 🔍 Шаг 4. Где хранится `.lic`

**После успешной активации** файл `.lic` может оказаться в **одном из трёх мест**:

| Путь | Когда используется |
|---|---|
| `/home/usr1cv8/.1cv8/1C/1cv8/conf/*.lic` | Если активировали от `usr1cv8` |
| `/opt/1cv8/conf/*.lic` | **Основной** каталог лицензий |
| `/var/1C/licenses/*.lic` | Альтернативный каталог (иногда создаётся автоматически) |

### 4.1. Найти файл

**В основном контейнере `1c-server`:**

```bash
docker exec -it -u root 1c-server find / -name "*.lic" 2>/dev/null
```

**Или в GUI-контейнере** (пока он ещё работает):

```bash
find /home/usr1cv8 /opt/1cv8 /var/1C -name "*.lic" 2>/dev/null
```

### 4.2. Скопировать в правильные каталоги

Сервер 1С ищет лицензию **в двух местах** (проверяет по очереди):

1. **`/home/usr1cv8/.1cv8/1C/1cv8/conf/`**
2. **`/opt/1cv8/conf/`**

**Положим в оба** — так надёжнее.

**Если нашли `.lic` в `/var/1C/licenses/`** — копируем:

```bash
docker exec -it -u root 1c-server bash

# Копируем в оба каталога
cp /var/1C/licenses/*.lic /opt/1cv8/conf/
cp /var/1C/licenses/*.lic /home/usr1cv8/.1cv8/1C/1cv8/conf/

# Права
chown usr1cv8:grp1cv8 /opt/1cv8/conf/*.lic /home/usr1cv8/.1cv8/1C/1cv8/conf/*.lic
chmod 666 /opt/1cv8/conf/*.lic /home/usr1cv8/.1cv8/1C/1cv8/conf/*.lic

# Проверка
ls -la /opt/1cv8/conf/
ls -la /home/usr1cv8/.1cv8/1C/1cv8/conf/

exit
```

### 4.3. Перезапустить сервис

```bash
docker compose restart 1c-server
sleep 15
docker compose ps
docker compose logs 1c-server --tail=20
```

**Ожидаемо:** `ragent` запускается **без ошибок про лицензию**.

## 🚨 Критично: привязка лицензии к MAC контейнера

### Что это значит

Community-лицензия **привязывается к MAC-адресу** сетевого интерфейса контейнера `1c-server`. Это **не «привязка к железу»** в обычном смысле, но эффект похож:

- MAC контейнера — **постоянный**, пока контейнер не пересоздан
- При **пересоздании** (`docker compose rm -f 1c-server`) — MAC **меняется**
- Лицензия на **новом MAC** — **не работает**
- Нужна **переактивация** (тратится слот)

### Что разрешено

```bash
docker compose stop 1c-server       # ✅ останавливает, MAC сохраняется
docker compose start 1c-server      # ✅ запускает, MAC тот же
docker compose restart 1c-server    # ✅ перезапускает, MAC тот же
```

### Что запрещено (без последствий)

```bash
docker compose rm -f 1c-server              # ❌ MAC изменится
docker compose down 1c-server               # ❌ удаляет контейнер
docker compose up --force-recreate 1c-server  # ❌ пересоздаёт контейнер
```

### Если пересоздание всё-таки нужно

1. **Деактивировать** лицензию на `developer.1c.ru`:
   - Личный кабинет → Комьюнити-лицензии
   - Найти привязанную к MAC → **Деактивировать**
2. **Пересоздать** контейнер
3. **Активировать** лицензию заново

На `developer.1c.ru` в разделе **«Комьюнити-лицензии»** видно:

| Поле | Пример |
|---|---|
| **Номер лицензии** | `500000155033` |
| **Состояние** | Действует до 27 сентября 2026 |
| **Имя компьютера** | `e50d3dd6fef4` (ID контейнера) |
| **Момент активации** | 01 июля 2026 17:39 |

**Имя компьютера** — это **ID контейнера** или его MAC. По нему можно понять, какая лицензия к какому контейнеру привязана.

## ⚠️ Возможные проблемы

### Проблема 1. Лицензия активирована, но не подхватывается

**Симптом:** на портале лицензия есть, но 1С при запуске требует лицензию.

**Причина:** `.lic` лежит **не в том каталоге**, или у него **неверные права**.

**Решение:**
1. Найти `.lic`: `docker exec -it -u root 1c-server find / -name "*.lic"`
2. Скопировать в **оба** каталога:
   - `/opt/1cv8/conf/`
   - `/home/usr1cv8/.1cv8/1C/1cv8/conf/`
3. Выставить права: `chown usr1cv8:grp1cv8`, `chmod 666`
4. Перезапустить: `docker compose restart 1c-server`

### Проблема 2. `.lic` в `--rm` контейнере

**Симптом:** активировали в `docker compose run --rm`, но `find` в основном контейнере **не находит** файл.

**Причина:** `--rm` контейнер удаляется после `exit`. Файл был в его **временной** файловой системе, а не в volume.

**Решение:**
1. **Пока** временный контейнер ещё жив — найти его ID: `docker ps | grep 1c-server`
2. Вытащить файл: `docker cp <ID>:/path/to/*.lic ~/projects/1c-server/1c-server/conf/`
3. **Или** — активировать заново с `-v 1c-server_1c_data:/home/usr1cv8`

⚠️ **Профилактика:** **всегда** монтировать volume при `docker compose run` для GUI.

### Проблема 3. `Хранилище сертификатов Linux не обнаружено`

**Причина:** нет сертификатов Минцифры.

**Решение:** см. [раздел 04](04-containers.md) — добавить в `Dockerfile`.

### Проблема 4. Все слоты заняты

**Симптом:** при активации `Все слоты (3) заняты`.

**Решение:** деактивировать ненужную лицензию на `developer.1c.ru`.

## ✅ Финальная проверка

После активации и копирования `.lic`:

```bash
# 1. Файл .lic на месте
docker exec -it 1c-server ls -la /opt/1cv8/conf/
docker exec -it 1c-server ls -la /home/usr1cv8/.1cv8/1C/1cv8/conf/

# 2. Права корректные
# Ожидаемо: usr1cv8:grp1cv8, -rw-rw-rw-

# 3. Сервер запущен
docker compose ps
# Ожидаемо: 1c-server Up

# 4. Кластер работает
docker exec -it 1c-server ps aux | grep -E "ragent|rmngr|rphost" | grep -v grep
# Ожидаемо: 3 процесса

# 5. Порт 1541 открыт
docker exec -it 1c-server bash -c 'IP=$(hostname -i); (echo > /dev/tcp/$IP/1541) 2>/dev/null && echo "1541 OPEN" || echo "1541 CLOSED"'
# Ожидаемо: 1541 OPEN
```

И **главное:** 1С открывается в режиме «Предприятие» **без запроса лицензии**.
