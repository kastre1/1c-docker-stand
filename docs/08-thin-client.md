## 🎯 Зачем это нужно

**Тонкий клиент** — это **программа на стороне пользователя**, которая:
- Подключается к серверу 1С по сети
- Отправляет команды (открыть документ, провести, отчёт)
- Получает **готовые данные** (не всю логику)
- **Вся тяжёлая логика** выполняется на сервере

**Плюсы:**
- Лёгкий (десятки МБ)
- Не требует установки СУБД на клиентской машине
- Работает через интернет

**Для нашего стенда:** тонкий клиент на Windows = **подключение к 1С в Docker**, как к настоящему серверу.

## 📥 Шаг 1. Установка тонкого клиента

### 1.1. Скачать дистрибутив

С `releases.1c.ru`:
- **Технологическая платформа 8.3 → 8.3.26.1540**
- **Клиент 1С:Предприятия (тонкий клиент) для Windows**
- Файл: `setup-thin-8.3.26.1540-x86_64.exe` или `.msi`

⚠️ **Версия клиента должна совпадать с сервером** (8.3.26.1540), иначе возможны проблемы совместимости.

### 1.2. Установить

1. Запустить установщик
2. Выбрать компонент **«Тонкий клиент»**
3. Установить
4. Запустить «1С:Предприятие»

## 🔧 Шаг 2. Подготовка: фикс с `hosts`

### 2.1. Симптом: имя сервера не резолвится

**При попытке подключиться** к ИБ из тонкого клиента Windows выдаёт ошибку:
```
Не найден сервер 1С:Предприятия: 13b42dfae82e
```

**Почему:** при создании ИБ в мастере (раздел 06) мы указали **`1c-server:1540`** — **имя Docker-контейнера**. Сервер 1С **внутри кластера** регистрирует ИБ с этим именем.

Когда тонкий клиент пытается подключиться к ИБ, он:
1. Получает от кластера **имя сервера**, к которому надо подключаться
2. Сервер отвечает: `13b42dfae82e` — это **ID контейнера `1c-server`** (внутреннее имя)
3. Клиент пытается **резолвить** это имя через DNS → **не находит** → ошибка

**Почему так:** в Docker-сети контейнер имеет **внутреннее имя** (`13b42dfae82e`), которое **не видно** из Windows. А в кластере 1С зарегистрировано именно оно.

### 2.2. Решение: добавить запись в `hosts`

На Windows открыть **Блокнот от имени администратора**:

1. Пуск → найти «Блокнот» → правый клик → **«Запуск от имени администратора»**
2. **Файл → Открыть**
3. Путь: `C:\Windows\System32\drivers\etc\hosts`
4. В фильтре типа файлов выбрать **«Все файлы»** (иначе `hosts` не увидите)
5. Открыть файл

**Добавить в конец файла одну строку:**

```
192.168.0.173 13b42dfae82e
```

**Разбор:**
- `192.168.0.173` — IP **Ubuntu VM**
- `13b42dfae82e` — **ID контейнера `1c-server`** (имя, которое ожидает клиент)

⚠️ **Важно:** ID контейнера (12 hex-символов) — **индивидуален для каждого развёртывания**. Узнать его можно командой:

```bash
docker ps --filter "name=1c-server" --format "{{.ID}}"
```

**Сохранить файл** (`Ctrl+S`).

### 2.3. Проверка

В **PowerShell**:

```powershell
ping 13b42dfae82e
```

**Ожидаемо:**
```
Обмен пакетами с 13b42dfae82e [192.168.0.173]...
Ответ от 192.168.0.173: число байт=32 время<1мс TTL=64
```

**Если `ping` не работает** — проверьте:
- Правильность написания ID
- Права администратора при редактировании `hosts`
- Отсутствие пробелов вместо табов (должен быть **пробел** или **таб** между IP и именем)

## 🚀 Шаг 3. Добавление ИБ в тонкий клиент

### 3.1. Запустить тонкий клиент

Пуск → **«1С:Предприятие»** (тонкий клиент).

### 3.2. Нажать «Добавить»

В стартовом окне → **«Добавить»**.

### 3.3. Выбрать тип

**«Добавление в список существующей информационной базы»** (не создание новой!).

### 3.4. Заполнить параметры

| Поле | Значение |
|---|---|
| **Имя базы** | `unf_test_ib` (или любое **отображаемое**) |
| **Тип расположения** | **«На сервере 1С:Предприятия»** |
| **Кластер серверов** | `192.168.0.173` или `192.168.0.173:1540` |
| **Имя информационной базы в кластере** | `unf_test_ib` |

⚠️ **Имя ИБ в кластере** — **точное имя**, которое вы задали при создании ИБ (раздел 06). Если ошибиться — будет ошибка `База не найдена`.

### 3.5. Завершить

Нажать **«Далее»** → **«Готово»**.

---

## 🎯 Шаг 4. Подключение к ИБ

### 4.1. Запуск в режиме «Предприятие»

1. Выделить добавленную базу в списке
2. Нажать **«1С:Предприятие»**
3. **Ожидаемо:** откроется окно 1С с пустой базой (нет конфигурации)

### 4.2. Запуск в режиме «Конфигуратор»

1. Выделить базу
2. Нажать **«Конфигуратор»**
3. **Ожидаемо:** откроется Конфигуратор (толстый клиент) с пустой конфигурацией

**В Конфигураторе** можно:
- Загрузить конфигурацию (`.cf`-файл)
- Изменить структуру данных
- Выгрузить конфигурацию

## ⚠️ Вторая Community-лицензия

### Когда требуется

**Тонкий клиент при подключении** к серверу может **потребовать лицензию** — в дополнение к серверной. Это зависит от:

- Типа лицензии (серверная/клиентская)
- Режима работы (Предприятие/Конфигуратор)

**В нашем случае:**
- **Серверная Community-лицензия** активирована на контейнер `1c-server`
- **Клиентская** может потребоваться для **толстого клиента** (Конфигуратора)

**Решение:** получить **вторую Community-лицензию** на `developer.1c.ru` и активировать её **на Windows-машине** через тонкий/толстый клиент.

### Как активировать вторую лицензию

1. Зайти на `developer.1c.ru`
2. Получить **новую** Community-лицензию (слот из 3-х)
3. При первом подключении клиента к ИБ — появится диалог **«Получение лицензии»**
4. Выбрать **«Активировать комьюнити-лицензию»**
5. Ввести логин/пароль от `developer.1c.ru`
6. Дождаться успеха

⚠️ **Учтите:** эта лицензия **привяжется к оборудованию Windows-машины** (не к контейнеру). Она **не переносится** между разными ПК.

## ⚠️ Возможные ошибки

### Ошибка 1. `Не найден сервер 1С:Предприятия: 13b42dfae82e`

**Причина:** нет записи в `hosts` (см. Шаг 2).

**Решение:** добавить `192.168.0.173 13b42dfae82e` в `hosts`.

### Ошибка 2. `Неверное имя пользователя или пароля`

**Причина:** неверные учётные данные от `developer.1c.ru` при активации клиентской лицензии.

**Решение:** проверить логин/пароль на портале.

### Ошибка 3. `Не удалось подключиться к серверу`

**Причина:** порт 1540 закрыт, или сервер не работает.

**Решение:**
1. `Test-NetConnection -ComputerName 192.168.0.173 -Port 1540` с Windows
2. `docker compose ps` на Ubuntu — `1c-server` должен быть `Up`
3. Проверить `docker compose logs 1c-server`

### Ошибка 4. `База не найдена`

**Причина:** неверное **имя ИБ в кластере**.

**Решение:** проверить точное имя в мастере 1С (раздел 06) или в GUI-списке баз.

### Ошибка 5. `Несовместимая версия клиента`

**Причина:** версия тонкого клиента **не совпадает** с сервером.

**Решение:** установить клиент **той же версии** (8.3.26.1540).

## 💡 Полезные приёмы

### Приём 1. Несколько баз в одном клиенте

В тонком клиенте можно добавить **несколько ИБ** — например, `unf_test_ib` (УНФ) и `ut_test_ib` (УТ). Переключаться между ними — одним кликом.

### Приём 2. Быстрое подключение через ярлык

Создайте ярлык в Windows:

```
"C:\Program Files\1cv8\common\1cestart.exe" "tp=srvr:192.168.0.173;rsrvr:1540;ref=unf_test_ib;"
```

Это **запуск без диалога** — сразу подключается к ИБ.

### Приём 3. Через веб-клиент

Если 1С развёрнута с веб-сервером (`ws`-компонент), можно подключаться **через браузер**:

```
http://192.168.0.173/unf_test_ib
```

**Но:** для этого нужен **веб-сервер** (Apache/nginx) внутри контейнера, которого у нас нет.
